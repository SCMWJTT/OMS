## 1. Purpose and source authority  *(OMS 7.4, 7.1)*

This Standard defines how ACE writes controlled documents so that ONE can read, test, link and display them without manual re-keying.

- **[R]** The approved Word document (and, for a Process, its paired process file) shall be the controlled source. Web views generated by ONE are derived representations.
- **[R]** Only an approved, numbered revision that has passed the publishing gateway shall appear in ONE's current views.
- **[R]** Every item ONE displays shall trace to document ID, revision and bookmark.

Publication chain: Author → Review → Approval → **Gateway** → Document Control release → ONE build → point-of-use notice.

## 2. Document hierarchy and types  *(OMS 7.1, 2.1)*

| Level | Layer | Types (code) | Answers |
|---|---|---|---|
| 1 | Policy | Manual (MAN), Policy (POL) | Why; commitments |
| 2 | Standard and Practice | Standard (STD), **Practice (PRA)**, Specification (SPC) | What must be true; how a discipline does it; technical performance |
| 3 | Process | **Process (PRS)** | Who does what, in what order, across functions |
| 4 | Procedure and Plan | Procedure (PRC), Plan (PLN) | Steps for one activity; site or event plans |
| 5 | Task and record | Work instruction (WIN), Form (FRM), Register (REG) | One task at one place; the record; the list |
| n/a | Supporting | Guideline (GDL) | Non-binding advice |

- **[R]** Each document below Level 1 shall name one parent document in `ODS.Parent`.
- **[R]** A Standard or Practice shall list the Processes and Procedures that implement it, in its "Implementing processes and procedures" table.
- **[R]** A Practice shall not repeat its parent Standard's requirements, and shall not contain step-by-step role sequences. Those belong in a Process or Procedure.
- **[R]** A Guideline shall contain no binding statements.

## 3. Numbering, revision and status  *(OMS 1.7)*

**Format:** `ACE-SSS-TTT-NNN[-LLL]`
- SSS = system code (Section 3.1);
- TTT = type;
- NNN = sequence;
- LLL = site code where the document applies to one site only: PAP, CHB, SAP, CPF, LND, PLB or HOF.

ENG uses discipline blocks 100 to 900 (ENG-STD-901 governs).

**3.1 System codes (26):** LDR, OMS, LEG, PPL, CON, STK, RSK, PSM, MOC, PRJ, ENG, AIM, MNT, WEL, OPS, COW, EMR, DOC, INC, PRF, ENV, OHH, SEC, plus the new **BPM** (Business Process Management), **LOG** (Marine and Aviation Logistics) and **HMA** (Hydrocarbon Measurement and Allocation).

**Rules:**
- **[R]** Draft revisions shall use letters (A, B, C…). Approved issues shall use two digits (01, 02…). The first approved issue after drafts A to C is 01.
- **[R]** Status shall be one of: Draft, In Review, Approved, Superseded, Withdrawn.
- **[R]** Placeholder numbers (for example ACE-AAA-STD-001) shall never appear in a submitted document.

**File name:** `ACE-SSS-TTT-NNN_Title_Words_Rev01.docx` (or `_RevA`).

## 4. Template and document anatomy  *(OMS 7.1)*

- **[R]** Every document shall be created from the current master template (v5). Copying an existing document to start a new one is prohibited.

**Order of parts:**
1. Cover
2. Document control table
3. Revision history
4. Approval and issue
5. Document map, including the implementing processes table (STD/PRA)
6. Numbered body sections
7. Appendices, including the controls table where the document establishes controls

The template contains only the ONE mark and the ACE logo, embedded. No linked pictures and no unused media.

**5.4 People.**
- **[R]** People shall be named as **Name — Job title**, exactly as in the ACE organisation register (`ACE_People.csv`).
- **[R]** Roles without names shall not be used for accountable positions.

## 6. Headings, bookmarks and OMS tags  *(OMS 7.1, 1.7)*

- **[R]** Body headings shall use Heading 1 to Heading 3. Each heading shall carry a bookmark (`_s` + stable number, e.g. `_s3_2`), and the bookmark shall not change between revisions while the section's meaning stays the same.
- **[R]** The Title paragraph shall carry the hidden bookmark `doc_title`.
- **[R]** Each heading shall be followed by an ODS Tag Line paragraph holding a plain-text content control:
  - alias **OMS Tags**;
  - tag **`ODS.OMSTags@<bookmark>`**;
  - content: OMS expectation numbers (1.1 to 10.5), comma separated, primary first.
- Tag scope runs from the heading down to the next heading of the same or a higher level. Tags are not inherited by sub-headings. Use 1 to 3 tags per section.
- **[R]** Every tag shall exist in the OMS expectation register (54 expectations).

## 7. Semantic styles and the "shall" rule  *(OMS 7.1, 7.2)*

| Binding styles: "shall" allowed | Non-binding styles: "shall" prohibited |
|---|---|
| ODS.Requirement · ODS.Responsibility · ODS.ApprovalRequirement · ODS.RecordRequirement · ODS.RiskControl | ODS.Warning · ODS.Note · ODS.Example · Normal · List styles · table cells · ODS.ProcedureStep |

- **[R]** "Shall" (and "shall not") shall appear only in the binding styles.
- **[R]** Each binding paragraph shall contain one requirement.
- Warnings are written as plain instructions ("Do not…", "Stop and…").

## 8. Control IDs  *(OMS 5.1, 6.4)* (new)

- **[R]** Every ODS.RiskControl paragraph shall contain a Control ID content control (alias **Control ID**, tag `ODS.Control@C-SSS-NNN`).
- **[R]** Control IDs shall be unique across ACE, allocated in blocks per document by the OMS Manager, and never reused.
- **[R]** A document that establishes controls shall include the appendix table: Control ID | Statement | Risk/threat | Section | Process step | Evidence.

Control IDs link documents to the Controls Register (ACE-RSK-REG-002), as defined in ACE-RSK-PRA-001.

## 9. Processes: the PRS document pair  *(OMS 7.1, 7.4)* (new)

- **[R]** A Process shall consist of a Word process description and a process model file (`ACE-SSS-PRS-NNN.json`) with the same number and revision, stored together.
- **[R]** The process description shall state the following:
  - the process owner, primary function, governing Policy and parent;
  - scope;
  - a SIPOC (suppliers, inputs, process, outputs, customers);
  - KPIs;
  - one narrative heading per step, bookmarked `_S01`, `_S02`… to match the step IDs.
- **[R]** Every step in the model file shall have one lane (role), a verb–object name and links (`doc_refs`, `controls`, `records`) that resolve.

The model file format is defined in ACE-BPM-PRA-002 (draft schema in the Handover, Section 11).

## 10. Tables, figures, references and links  *(OMS 7.1)*

- **[R]** References to ACE documents shall use the full number and title on first use. Section references shall use `ACE-SSS-TTT-NNN §x.y`.
- **[R]** Figures shall be embedded, not linked, with alt text.
- Tables use the ODS table styles. No "shall" in cells (Section 7).

## 11. Publishing gateway  *(OMS 7.4, 9.5)*

- **[R]** Every submission shall pass the gateway. Errors block publication. Warnings are listed in the report.

| # | Check | Result if failed |
|---|---|---|
| G1 | File name and number format; site and system codes valid | Error |
| G2 | Revision and status rule (letters ↔ Draft; digits ↔ Approved) | Error |
| G3 | All 23 custom properties present, standard names, none extra | Error |
| G4 | Control table = custom properties = built-in Title/Subject/Tags | Error |
| G5 | `doc_title` bookmark present; title tags match ODS.TitleOMSTags | Error |
| G6 | Every heading has a tag line; tags valid; no duplicate tag controls; no orphan tag controls | Error |
| G7 | "Shall" only in the binding styles | Error |
| G8 | People match the org register (Name — Job title) | Error |
| G9 | Control IDs well-formed, unique, in the allocated block | Error |
| G10 | ODS.Parent exists in the register | Error |
| G11 | Referenced ACE documents exist (current or planned) | Warning (planned) / Error (unknown) |
| G12 | PRS: Word ↔ JSON agree (ID, revision, steps, bookmarks); links resolve | Error |
| G13 | STD/PRA: implementing processes table present | Warning |
| G14 | No linked images; no unused media; file under 2 MB | Warning |
| G15 | Valid Word XML (schema order; no repair needed) | Error |
| G16 | No `~$` lock files or temporary files in the submission | Error |

Exceptions to gateway rules are raised through ACE-OMS-STD-002.

## 12. ONE web views and acceptance  *(OMS 7.4, 1.6)*

ONE builds the following from the published set:
- the **OMS wheel** (element → expectation → sections);
- the **library**;
- the **reader**;
- **element** pages;
- **roles**;
- the **document map**;
- **processes** (swimlane reader);
- **controls**;
- the **gateway report**;
- search.

The **dashboard** animates the history from issue and effective dates and revision histories.

- **[R]** Each view shall show the document ID, revision and status, and link back to the controlled Word source.

## 13. Records and repository  *(OMS 1.7, 7.4)*

**Repository folders (SCMWJTT/OMS):**

| Folder | Holds |
|---|---|
| `finals/` | approved |
| `drafts/` | in work |
| `processes/` | PRS pairs |
| `registers/` | registers |
| `templates/` | current template only |
| `superseded/` | previous revisions |

- **[R]** Superseded revisions shall be moved to `superseded/`, never deleted.
- **[R]** Only the current template shall be kept in `templates/`.
